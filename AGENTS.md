# Architecture rules
- Render backend working steps through a shared chat component for pending and completed answers so both views use the same presentation.
- Persist completed working steps inside the existing assistant content payload so history reloads need no separate storage schema.- Chat messages stream directly from n8n (src/lib/answerStream.ts) only behind the ?stream=1 flag; the poll stays the source of truth and fallback, and only the get_result payload is ever stored — edge functions cannot hold long streams on the current plan.
- Chat list items, the answer card and Md are React.memo with module-level Markdown config, and the composer text lives in ChatInput, so typing, streaming and progress never re-render finished answers.
- Streamed answers number source pointers [[...]] as [n] during streaming (per-turn map in runStreamTurn) and render them as non-clickable cite-markers via CiteStaticContext; streamView is cleared only in the same commit that places the checked answer, so the finish never blanks or re-layouts the text.
- Dictation (src/lib/dictation.ts) records one complete audio file per segment cut at a pause measured relative to the room level (forced cuts at the limit overlap 2 s and are joined at the longest shared word run (src/lib/overlap.ts) before release), stores each segment in IndexedDB before uploading it to the n8n dictation webhooks, and deletes it only after status "transcribed"; chat-proxy is never used for audio, only for the client_error report, whose details ride in `message` because chat-proxy drops non-whitelisted keys.
